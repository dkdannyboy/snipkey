# SnipKey 개선 목록

작성일: 2026-09-25 · 기준 버전: 1.3.2 (build 10)

세 가지 관점에서 살폈다.

1. **경쟁 앱 비교**: TextExpander, Espanso, aText, Typinator, Raycast, Alfred, Keyboard Maestro, PhraseExpress, Text Blaze, Beeftext, AutoHotkey
2. **코드 점검**: 버그 위험, UX 거친 부분, 테스트 공백
3. **플랫폼 확장**: Windows 판에 무엇을 옮길지

범례: ✅ 이번 차수에 반영 · 🕓 다음 차수 후보 · ✋ 일부러 하지 않음

## 3. UX 거친 부분 (다음 차수 후보)

- 스니펫을 삭제할 때 확인이나 되돌리기가 없다.
- "매크로 삽입"이 커서 위치가 아니라 항상 끝에 붙는다.
- 검색 팔레트가 포커스를 잃어도 떠 있다.
- 채우기 창이 꺼진 구간 안의 필드도 보여 준다.
- 저장소 오류 문구가 한국어로 고정돼 있다(`Store.swift`).

## 4. Windows 판

macOS 판의 동작 규칙을 그대로 옮긴 **SnipKey for Windows**를 `windows/`에 둔다.

| 영역 | 방식 |
|---|---|
| 핵심 로직 | `SnipKey.Core` (.NET 8). 모델, 매크로 파서, 약어 매처, 검색, 저장소를 담고 macOS에서도 테스트한다 |
| 키 감지 | `WH_KEYBOARD_LL` 저수준 훅. 콜백은 즉시 반환하고 실제 작업은 메시지 루프에 넘긴다. 1초 제한을 넘기면 훅이 조용히 제거되기 때문이다 |
| 입력 | 백스페이스는 `SendInput`으로 보낸다. 짧은 텍스트는 `KEYEVENTF_UNICODE`로 치고, 긴 텍스트나 여러 줄은 클립보드에 붙여 넣은 뒤 원래 클립보드를 복원한다 |
| 자기 입력 무시 | 우리가 보낸 이벤트에 `dwExtraInfo` 표식을 붙여 걸러 낸다 |
| 파일 호환 | Mac과 같은 `store.json`을 쓴다. 날짜 형식, 대문자 UUID, `version: 2`, `expansionCount`를 맞추고, 모르는 키(`macros`, Mac 전용 설정)는 그대로 보존한다 |
| 키 훅 스레드 | 훅은 전용 스레드의 메시지 루프에서 돌고, UI 스레드로는 순서를 지켜 넘긴다. UI가 잠깐 멈춰도 시스템 전체의 키 입력은 멈추지 않는다 |
| 입력 가드 | 시각이 아니라 입력 **순번**을 쓴다. 약 15ms 단위 시계로는 같은 틱에 들어온 다음 키를 놓치기 때문이다 |
| 제한 | 관리자 권한으로 실행 중인 앱에는 UIPI 때문에 입력할 수 없어 감지 후 알린다. IME가 조합 중일 때(한글·가나·중국어)는 확장하지 않는다. 물리 키 기준 매칭은 다음 차수로 미룬다 |
| 검증 | 핵심 로직 테스트 65개(Mac이 쓴 `store.json` 왕복 포함)와 `.exe` 빌드를 확인했다. Windows 실기 테스트는 아직 하지 않았다. CI(`.github/workflows/windows.yml`)가 windows-latest에서 `--selfcheck`로 실행해 본다 |
